What a Passport is

An IdentyClaw Passport is a persistent, on-chain identity credential for an AI agent — like a passport for a person, but for a software agent. It’s a subject-owned token on a NEAR registry, identified by a unique 12-character “facial” code people can recognize visually.

What it’s good for: letting agents prove who they are to strangers on channels nobody controls (chat, A2A, webhooks, even QR/sound), without re-registering at every service. Verification answers: “Is this the same attributable agent on the registry I trust, and do they currently control that credential?” — not “Are they allowed to call my API?” or “Who is the human behind them?” Those stay other layers (OAuth, KYC, authz, etc.).

Facial ID

Every Passport’s 12-letter tokenId encodes facial traits peers can resolve as a readable persona—a personable, immediately recognizable identity useful for interfacing with humans. Example: chsjlpchbngh resolves to a feminine, square-faced, East-Asian senior with bow-shaped lips and freckled, ruddy skin—traits a human can recognize. The face id encodes a recognizable face, and that unique face matches its face id. Give it a Test Drive.

Many-to-many agent collaboration

At scale, 1,000 × 1,000 agents collaborating requires 1 million pairwise API keys—or only 2,000 Passports, one per agent. Webhooks face the same pairwise trap in the same scenario: 1 million peer-pair HMAC shared secrets—or the very same Passport you already have, as they are digitally signed in origin. Identity scales linearly, not geometrically.

Sovereign

Your NEAR account holds and controls the Passport. Signing keys stay with you—not in a central identity database, not attached to any provider. You mint your identity; you do not register with IdentyClaw to exist. Change key pair as often as you like while keeping the same persistent identity not only peers can verify, but anyone can verify.

Multi-channel

One Passport across API, messaging, email, and peer protocols—not bound to any one address or URL. HOLA proofs are compact, signed strings you can embed in API payloads, email, Telegram, WhatsApp, Signal, Discord—or, if you prefer, Morse-encoded drums.

Get Started

Install OpenClaw or Hermes, mint a Passport to the NEAR account it prints, and your agent has an identity. Keys stay on disk. Never paste private keys into chat.

OpenClaw

  1. 1

    Have OpenClaw

    Already running an OpenClaw gateway? Continue to step 2. Otherwise install OpenClaw from the getting started guide, then put a background gateway in place before any gateway restart:

    openclaw gateway install
openclaw gateway status

    A full host with Podman and nginx TLS is the openclaw-agents template.

  2. 2

    Install the Passport plugin

    This is the plugin you need: API login, HOLA, identity, and DID. Current OpenClaw may require --accept-capabilities. Restart loads the plugin; on first start with no credentials it can auto-write a NEAR account under ~/.openclaw/secrets/near-credentials/. Keys stay on disk. Never paste private keys into chat.

    openclaw plugins install clawhub:@identyclaw/openclaw-identyclaw-plugin --accept-capabilities
openclaw gateway restart

    Prefer the auto-bootstrap account id when the gateway printed one. To run the operator CLI yourself: ClawHub install does not put the package bin on your PATH — link it from the installed plugin package:

    mkdir -p "${HOME}/.local/bin"
# Point PLUGIN_ROOT at the installed plugin dir (often under ~/.openclaw/extensions/)
ln -sfn "${PLUGIN_ROOT}/scripts/generate-near-account.mjs" "${HOME}/.local/bin/identyclaw-generate-near-account"
export PATH="${HOME}/.local/bin:${PATH}"
identyclaw-generate-near-account

    Paste only the printed 64-character hex NEAR account id (OpenClaw labels it implicit_account_id) at checkout — never a private key or JWT.

    Advanced: webhooks, A2A, and guest HTTPS

    Same host, same NEAR credentials. Set PLUGIN_FLAGS once if installs ask for capability consent:

    PLUGIN_FLAGS=(--accept-capabilities)
openclaw plugins install clawhub:@identyclaw/openclaw-identyclaw-webhooks-plugin "${PLUGIN_FLAGS[@]}"
openclaw plugins install clawhub:@identyclaw/openclaw-a2a-plugin "${PLUGIN_FLAGS[@]}"
openclaw plugins install clawhub:@identyclaw/openclaw-identyclaw-httpbearer-plugin "${PLUGIN_FLAGS[@]}"
    • webhooks — RODiT-signed ingress on /hooks/wake and /hooks/agent
    • A2A — peer messaging with Passport JWTs
    • HTTP bearer — guest HTTPS when there is no Passport

    Public HTTPS / TLS for these is operator setup — follow openclaw-agents; this page is not a full ingress runbook.

  3. 3

    Optional: a domain

    Point a public HTTPS domain at your agent if you want Telegram, A2A, or webhooks to reach it. That hostname serves the Agent Card and signed webhooks at /hooks/wake and /hooks/agent. Certificates and reverse-proxy TLS are on you (or the openclaw-agents template) — not covered here. Skip this and mint anyway if you only need the Passport.

  4. 4

    Obtain a Passport

    Take that 64-character hex NEAR account to purchase.identyclaw.com and mint a Passport to it. Buy once — no subscription. After on-chain confirm, restart and activate the home API session from the TUI (or Control UI chat). Personal and Enterprise tiers are on Pricing.

    openclaw gateway restart
openclaw tui

    In the TUI, ask the agent to call identyclaw_ensure_session, then identyclaw_get_my_identity — you should see your Passport (including token_id). On-chain confirm can take a short while; until then identity lookup fails with no Passport yet (local account exists) — wait and retry.

  5. 5

    Write IDENTITY.md

    Still in the TUI (or reopen with openclaw tui), ask the agent to read its IdentyClaw passport and write that into IDENTITY.md.

    In the TUI:

    please read all your idcp passport details and use that information to write IDENTITY.md

Hermes

Stock Hermes Agent plus the identyclaw-auth plugin. Install Hermes, run install-deps (prints account_id), mint, then hermes identyclaw me. Do not run OpenClaw and Hermes IdentyClaw plugins on the same host — leave OpenClaw stopped for this path.

  1. 1

    Install Hermes

    Official installer; hermes lands in ~/.local/bin. Expect a few minutes and about 2.3 GB under ~/.hermes — it is not stuck. Vanilla Hermes stops here; Passport comes in step 2.

    curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash -s -- --non-interactive --skip-browser --skip-computer-use
hermes --version

    If command -v hermes fails: export PATH="$HOME/.local/bin:$PATH" (persist in your shell rc if needed).

  2. 2

    Install the Passport plugin

    Needs libatomic for IdentyClaw/RODiT. Answer y to enable (or pass --enable). A GitHub install may warn about a custom (unreviewed) source — expected. install-deps runs npm, and if ~/.hermes/secrets/near-credentials/ is empty creates a 64-character hex account, prints account_id, and seeds NEAR_CREDENTIALS_FILE_PATH in ~/.hermes/.env.

    # Fedora / RHEL
sudo dnf install -y libatomic
# Debian / Ubuntu
sudo apt-get update && sudo apt-get install -y libatomic1

hermes plugins install discernible-io/hermes-identyclaw-auth --enable
hermes identyclaw install-deps   # npm + NEAR account if missing

    Paste only that printed account_id at checkout — never a private key or JWT. Re-runs are safe; reprint with hermes identyclaw enroll (no overwrite). If Hermes says “Skipped Node deps — run hermes plugins install again,” ignore it — run install-deps as above.

  3. 3

    Obtain a Passport

    Open purchase.identyclaw.com, paste that account_id, and mint. Buy once — no subscription. On-chain confirm can lag; until then hermes identyclaw me returns RODIT_NOT_FOUND — wait and retry. Tiers are on Pricing.

  4. 4

    Confirm Passport

    Login happens inside the plugin. You should see Passport fields including token_id. JWTs stay under ~/.hermes/secrets/identyclaw/; the CLI never prints full JWTs.

    hermes identyclaw me
Advanced: day-to-day, IDENTITY.md, Showcase 
hermes identyclaw create_hola --recipient MUNDO
hermes identyclaw verify_hola --hola 'HOLA/…'
hermes identyclaw request GET /api/agents

In Hermes chat, ask it to read its IdentyClaw passport and write IDENTITY.md:

please read all your idcp passport details and use that information to write IDENTITY.md

Advanced: ensure_session, gateway, sidecar, peers

hermes identyclaw ensure_session is for --force remint, federated peers (--base https://peer…), or debugging — not the happy path. Returns metadata only — never the full JWT.

hermes identyclaw ensure_session --force
hermes identyclaw ensure_session --base https://peer.example.com

Restart the Hermes gateway only if you want IdentyClaw tools inside chat/gateway; the CLI mint path does not need it. Optional Passport-only: disable sidecar autostart with IDENTYCLAW_SIDECAR_AUTOSTART=false in ~/.hermes/.env.

Peer stack (sidecar, A2A, webhooks) — see hermes-agents:

hermes identyclaw sidecar start
hermes plugins install discernible-io/hermes-identyclaw-a2a
hermes plugins install discernible-io/hermes-identyclaw-webhook
Hermes FAQ
hermes identyclaw me says RODIT_NOT_FOUND after mint?
On-chain confirm can lag. Wait, then retry hermes identyclaw me. Do not re-enroll to mint again.
Need the account_id again?
hermes identyclaw enroll reprints the same id (already: true) and does not overwrite credentials.
Override HERMES_HOME?
Optional. Default is ~/.hermes. Export only if you keep Hermes elsewhere.
System Node.js?
Hermes-bundled Node under ~/.hermes/tools/node-… is enough for install-deps. System Node.js 22.19+ only if you run plugin scripts outside Hermes.
